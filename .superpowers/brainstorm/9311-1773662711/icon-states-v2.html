How processing sub-states work

The processing status is the parent. Within it, the backend reports which pipeline phase is active. The icon always shows the specific phase, never a generic "processing" spinner:

Flow: planning → ready → processing:transcribing → processing:analyzing → processing:synthesizing → completed

If the backend can't report the specific phase (edge case), we fall back to a generic animated spinner. But in practice, every processing state maps to a phase.

Animation consistency: all active states animate

Static states: planning (+), ready (play), completed (check), archived (archive), error (! after initial shake). No gratuitous motion.

Animated states: Every processing phase has continuous animation — spinning, pulsing, orbiting. This immediately communicates "work is happening" at a glance.

Where icons come from

Lucide React (already in the project) handles most icons: Plus, Play, Check, AlertCircle, Archive, Sun. These match the existing icon style throughout the app.

Custom inline SVGs for the two cases lucide doesn't cover well:

1. Transcribing waveform — 4 animated bars. Lucide has AudioLines but it's static and doesn't animate well. Custom SVG gives us bouncing bars.

2. Synthesizing network — 3 orbiting nodes with pulsing connections. Lucide has Network but it's too detailed at 14px. Custom SVG is simpler and animates cleanly.

Both custom SVGs follow lucide's conventions: 24x24 viewBox, 2px stroke weight, round caps. They'll blend seamlessly.
